岗位筛选助手使用说明

独立版 0.1.2。各网站分别启动，总台可切换或合并；表格为默认展示方式，可切换卡片，只自动保存收藏。

1. 安装与更新

  1. 解压安装包到独立的固定文件夹，不覆盖其他插件。
  2. 打开 Edge 或 Chrome 的扩展管理页面，启用开发者模式。
  3. 选择“加载解压缩的扩展”，指定包含 manifest.json 的文件夹。直接使用源码时选择 extension。
  4. 把“岗位筛选助手”固定到工具栏。

更新已有插件时，在原扩展目录替换资源后点击扩展管理页的“重新加载”。保留原扩展身份才能读取已有收藏。首次升级到本版会迁移旧收藏，随后移除旧普通岗位数据。

0.1.0 是首个 GitHub 公开版本，此前 0.2.x、0.3.x 是本地试制编号。已经加载本地试制目录时，替换原目录资源后重新加载即可；不要先移除扩展，以免丢失收藏。若浏览器拒绝较低编号的覆盖，先备份收藏，再使用独立目录加载公开版并导入收藏。

2. 从当前招聘列表开始

  1. 在原网站选好招聘类别、公司、城市等范围，建议先回到该范围的第一页。
  2. 点击浏览器工具栏的插件图标，打开该网站右下角的小窗。浏览器首次可能询问是否允许读取当前网站；插件同时准备一个总筛选台标签页。
  3. 在小窗设置专业检索词和“我的学历”，点击“开始检索”。“隐藏学历明确不符”只隐藏已识别到学历冲突的岗位，学历未知、专业待确认仍保留。“打开总筛选台”可填写完整专业、城市等条件，也可选择当前来源后在总台启动。学历与总台共用，未设置时不判断学历。
  4. 原列表会自动翻页、点击已识别的加载更多，或向下滚动触发后续岗位，保留原网页已有筛选条件。采集期间避免同时修改原列表。
  5. 插件先收集岗位，再补充详情；静态详情直接读取，动态详情按来源使用不抢焦点的工作标签页加载。

若列表和详情位于不同网站，插件保留详情原链接，缺少权限时显示“详情待授权”，不会把它当成没有专业要求。点击小窗“授权详情站点 ↗”进入总台，再点击“授权详情站点并继续”，浏览器允许后从本轮进度接着读取。拒绝授权则保留已有结果，仍可人工打开原页；不会自动申请所有网站权限。

插件从当前页读取后续分页。如果从中间页开始，会明确提示未覆盖前面的分页。它不会自行扩大到别的招聘类别、网站或子公司入口。

同时打开多个招聘网站时，在各网站点击插件图标、分别开始。没有启动的网站不会自动采集。总台“结果来源”可以只看一个网站，也可以“合并所有本轮来源”。个人条件和筛选条件在本轮各来源之间共用。

小窗复用没有变化的岗位行，减少大列表刷新时的重复创建，状态更新仍同步；显示当前来源全部筛选结果，可以在小窗内滚动查看、收藏、点击“查看原岗位”和跳转总台详情，不再限制前5条。同站翻页后，已打开的小窗会恢复；已经收起的小窗保持收起。没有固定采集总数上限；已采集且符合筛选条件的岗位都会显示。

“暂停”保留本轮内存进度，“继续”接着读取并沿用本轮进度和访问间隔。请保持总筛选台标签页打开，切到其他标签页不影响任务；刷新或关闭总台会停止全部本轮任务，并清空普通结果和暂停进度。

切到别的标签页浏览其他网站，原任务继续；如果把正在采集的原标签页本身导航到另一网站，在下一次来源检查时停止该任务并保留已有结果，已发出的单次读取可能先完成。此时不会自动扫描新网站，需在新网站重新打开插件并主动开始。原招聘页与总台都需保持打开；浏览器退出或崩溃不能继续。

小窗与总台可以为当前来源选择采集速度：默认“稳妥 · 3 秒间隔”，可选“较快 · 2 秒间隔”。采集中先暂停，修改后点击继续，可保留本轮进度；合并查看时需先选择具体来源才能改速度。速度仅在当前会话保留，新来源默认稳妥。较快模式可能更容易触发网站限流，整体提速取决于网络和页面加载，详情完整性检查和等待超时保持不变。

同一实际访问站点的翻页、滚动、详情点击或读取共用间隔；同站多个标签页及多个来源共用的详情站点采用其中较慢的设置。开始等待后出现较慢任务，会延长排队间隔；切到较快模式不会缩短上一动作应保留的间隔。不再设置固定岗位数、分页数和访问操作总数上限。读取到列表结束、页面重复或没有新增岗位后停止翻页，继续补读已发现岗位详情。大列表分批显示进度，暂停和继续保留已发现岗位；你可以随时结束并清空。取消总量上限不影响所选访问间隔；岗位多时需要更长时间，浏览器退出或总台关闭后不会继续。

3. 收藏就是你的投递清单

点击岗位旁的“☆ 收藏”，保存该岗位的原文、职责、来源链接和采集时间。在右侧详情或卡片中可记录“准备投递”“已投递”“不考虑”等状态。投递状态由你手动填写，插件不会替你提交申请。

下次打开默认显示“我的收藏”；其他未收藏岗位不自动保存，也不会重新出现。只有你再次回到招聘网站并开始采集，才会产生新的普通结果。

取消收藏会移除保存的岗位快照。当前筛选页面里还存在的临时岗位可以继续查看，关闭后清空。收藏不会因为开始新一轮采集而被覆盖。

4. 表格、卡片与关闭操作

表格列出岗位、公司、城市、学历、专业、判断、采集状态、截止时间和操作。冲突会标明“学历冲突”“英语冲突”等具体项目，并直接显示原因；小窗和卡片也显示这些原因。点击岗位标题，右侧展开详细要求与逐项原文依据。

表格、卡片、小窗和右侧详情均有与收藏并列的“查看原岗位”按钮，在新标签页直达该岗位的原详情。若只识别到列表链接，则标为“查看来源列表”，供你在来源中继续寻找；不会把列表链接冒充详情链接。

“卡片”显示要求摘要；显示方式会记住。每页 25 条。窄屏表格可在表格内部横向滚动。

小窗右上角“×”只收起小窗，任务继续；再次点击该网站的工具栏图标可以展开。“结束并清空”停止该来源并清除未收藏结果，已收藏岗位保留。总台选择合并来源时，“结束并清空”作用于全部本轮任务。

详情右上角“×”或 Esc 关闭详情。总筛选台右上角“×”关闭总台并停止全部采集，原招聘标签页保留。页面上的区域选择浮条同样有关闭按钮和 Esc 取消。

5. 设置条件与理解判断

填写学历、毕业年份、完整专业、工作经验、英语条件；空白项不参与自动比较。城市、岗位内容、公司、专业检索词、福利和排除关键词可以组合。

专业有两种输入，作用不同：

  • “我的完整专业”：填写毕业专业全称，例如“电子信息科学与技术”。用于资格判断，输入时可选择本科目录名称；简称不会据此直接判定符合。
  • “专业检索词”：填写“电子信息”“电气”“机械”等部分名称。适用于任意文字，同一栏多个词满足任意一个即可。空格和全角文字会规范化。

插件先提取“专业要求、所学专业、专业背景”等独立字段，再识别人资资格、任职资格、应聘条件等栏目，包括“【任职资格】”“[应聘条件]”“（岗位要求）”等写法。单个详情中其他栏目及结构化职位描述里的明确专业条款也会补查，不依赖固定标题；同一段落中混写的专业与技能分别识别。没有“专业”二字的完整本科专业列表也可以识别。“电气工程及其自动化专业”能命中“电气”；“熟悉电气设备”属于技能，不算专业命中。“专业不限”单独显示；“不接受电气类专业”是排除条件，不算接收专业。

默认保留专业词命中、范围可能覆盖、专业不限和信息待确认的岗位。明确其他专业且未命中、明确排除检索词的条目不进入默认专业检索结果。若只想看文字直接命中条目，选择“专业检索范围 → 只看专业词命中”。范围推断不会计为文字直接命中。

默认按专业匹配排序，其他明确硬性冲突放到后面。匹配的专业名称在专业列第一行加粗，检索词高亮；完整专业原文继续显示。按本科目录判断可能属于“理工类、工科类、理学与工学等相关专业”等范围时，会说明门类依据并保留待核对；并列门类按任一适用范围处理，企业最终如何界定范围仍以招聘原文及解释为准。右侧详情区分检索结果与资格判断；关键词命中不代表专业资格符合。

内置参考为教育部《普通高等学校本科专业目录（2026年）》，教高函〔2026〕2号，2026年4月7日，2026年10月8日核对。共883个专业、92个专业类，离线使用，仅覆盖本科，不覆盖专科、研究生、历史更名或企业自定分类。设置“本科”并填写已识别的全称时，会显示如“电子信息科学与技术 → 电子信息类”的参考关系；按专业类或“相关专业”招聘仍待确认。原文指定其他年份或其他层次目录时不套用2026年本科类别关系。明确排除你的完整专业或已核实的本科专业类时提示冲突，优先于“专业不限”；存在例外或前后冲突时保留待确认。

同一栏用逗号分隔的关键词满足任意一个即可，不同栏需要同时满足。“排除关键词”是文字匹配，可能把“无需出差”也排除，应结合结果数量核对。

  • 所选条件未见冲突：仅限填写的条件及程序提取到的信息。
  • 待确认：缺失信息、相关专业、放宽条件或额外资格需要看原文。
  • 存在明确冲突：某项已填写条件与已识别要求不一致，或已过截止时间。例如填本科、岗位要求硕士，会显示“学历冲突”及具体学历要求。专业未提取到只会提示待确认，不会因此判专业冲突；学历冲突和专业待确认可以同时存在。

学历要求不限定于任职栏目：顶部摘要、表格、独立字段和正文一起核对。顶部的“本科及以上”等会保留完整修饰词；列表学历在详情缺失时保留并标注来源。顶部和正文给出不同学历时，显示“学历表述不一致（看原文）”并保留待核对，不自动判通过。推荐岗位、导航和隐藏模板中的条件不参与当前岗位判断。学历优先与硬性要求分别处理。专业类别、技能熟练程度、学校范围、证书、全日制、年龄等复杂要求仍需核对。读到详情不代表它写全了条件。

6. 采集状态与识别纠正

进度分别显示已读分页、已发现岗位、要求完整、待读、不完整与失败。采集中“详情待读，专业尚未核对”表示还在排队；读取结束后仍没提取到专业条款，表格、卡片和小窗用醒目的提示显示“未检测到专业要求”，不代表原文专业不限。读取失败仍显示失败，不冒充读取完成；已识别到宽泛或模糊的专业范围仍显示其依据与待核对提示。只提取到学历摘要时会继续加载动态正文，始终只有摘要则保留“不完整”。判断状态和采集状态分开显示，缺失要求不当作没有门槛。

只有已读岗位数与页面报告总量一致、且未从中间页开始时，才显示数量一致；这仍只指当前筛选列表。页面没有报告总量时，全列表覆盖情况保持未知。

自动识别不准时，展开“识别不准？”区域，选择指定岗位区域、岗位标题或下一页。回到原网页点选目标，可点击“扩大区域”，然后点击“使用选择”。规则只保存在本机；页面结构变化后可清除并重新指定。

不保证识别任意网站。无文字标题、未授权详情、跨站重定向、iframe、PDF、图片要求、登录或验证码、复杂弹窗、虚拟列表或特殊滚动容器等情况可能无法完整读取。滚动后没有新增岗位会停止并提示；若数量未达到页面总数，仍不声称全量。界面保留缺失或失败条目。

返回403（拒绝访问）、429（访问过于频繁），或识别到明确人机验证、验证码、访问限制提示时，会停止使用该访问站点的相关来源任务，保留已发现结果，不再自动读取下一岗位。多个来源使用同一详情站点时一并停止，未使用该受限站点的任务仍可独立运行。来源页和已授权动态工作页的同源文档及接口状态会被观察；特殊跨站接口或无法识别的验证可能不在覆盖范围内。

网站限制会触发至少10分钟的冷却；如果网站要求更长的 Retry-After 等待时间，则按更长时间等待。冷却期间重复点击开始不会继续发起采集；到期也不会自动重试。请停止访问并稍后在原网站人工核对，不要尝试绕过限制。保护停止和达到上限不显示“继续”，手动暂停仍可续读。

这些措施用于减少访问负担，不提供隐身或规避检测功能。限速不控制网站自己加载的图片、脚本或后台请求，也不保证不会被限制；仍应遵守网站的访问规则。

7. 导出与恢复

“导出结果 CSV”主动导出当前筛选的全部结果分页，包含原文、来源网站、列表与详情链接，可用 Excel 打开。

“备份收藏”只导出收藏和投递状态，不包含普通结果、个人条件和网站识别规则。“导入收藏”合并已有收藏；旧版岗位备份只恢复其中标为收藏的记录，其余丢弃。

导入上限为 6000 条、15 MB。备份可能包含你收藏的实际岗位和链接，按个人资料保存。页面没有自动上传功能。

8. 本地存储与访问权限

长期保存的内容只有收藏岗位、个人筛选条件、显示方式和你点选的网站规则。普通结果和任务进度不写入浏览器本地或会话存储，只在总台内存中，刷新、关闭后释放。浏览器会话存储记录标签页绑定、小窗状态和访问限制冷却元数据，不记录普通岗位内容。刷新或关闭总台不会清除尚未到期的站点冷却期。

扩展只在你主动启动时读取绑定的招聘网页，按需申请当前站点及实际遇到的详情站点权限。列表翻页、展开详情和岗位标题读取不会点击申请、登录或提交按钮。原列表切换到其他站点会停止；已授权的跨站岗位详情由独立工作页读取，列表仍绑定原来源。未经授权的详情不发起请求。

本版新增“观察网络请求状态”权限，用于发现你授权站点的403/429响应。只处理采集来源及工作页的相关状态；不读取响应正文作为监测日志，不修改网络请求、不读取密码、不上传浏览记录。浏览器更新时如提示新增权限，需要允许后才能使用该版本。

安装包不含具体公司入口、硬编码招聘域名、真实岗位数据、个人材料或账户。示例和教程截图均为虚构。目录来源链接仅供核对，不在运行时请求目录或发送个人条件。运行时读取到的实际公司名称和网址只用于你的本地筛选与收藏。

“AI 辅助 · 待配置”表示已预留接口，当前没有 AI 服务、密钥或模型调用。以后接入时，需要明确本次使用哪些岗位和个人条件，辅助结果单独标明并保留原文依据。
